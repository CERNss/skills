# 存量审计：静默降级 / 过度防御

这是**存量**治理，一次性清理旧代码。增量治理靠 semgrep + pre-commit + CI（`fallback-onboard` skill），
两者配合才闭环：审计一次清干净，拦截保证不再长回来。

审计范围默认是当前仓库全量代码；用户指定了模块 / 目录 / 语言就只审那部分，
但要在报告开头写清实际审计范围，不要让人误以为是全量结论。

下面是执行正文，直接照做。

---

你是一名资深工程师，负责审计本仓库的「静默降级 / 过度防御」代码。
目标不是把所有 try/except 删掉，而是把**掩盖故障的兜底**和**保护业务的兜底**分开处理。

## 一、判定标准

### 判定为「过度防御」（必须改为直接报错）

1. **静默掩盖核心配置或凭据错误**
   外部服务未启动、API Key 失效 / 缺失、网络不可达时，静默切到本地模式或默认模式。
   结果：部署配置错了，服务却「正常」启动，故障现场被推迟到几小时后的下游。

2. **无效回退**
   多级探测（多个路径 / 多个候选源）全部未命中后，返回空值、`None`、裸文件名之类的占位。
   下一阶段必然崩溃，且崩溃点已经丢失了「原本在找什么、找过哪些位置」的排查上下文。

3. **注入伪造数据与假规划**
   调用失败时写死一段通用模板、伪造一份全 `False` 的报告、编一个默认计划继续往下走。
   结果：错误数据污染了系统状态，比直接崩溃难查一个数量级。

4. **关键前置链路失败时盲目执行**
   规划器 / 鉴权 / 参数解析等前置环节已经崩了，代码不但不阻断，反而带着空输入继续跑，
   空耗资源、写脏数据。

5. **弱化错误语义**
   宽泛 `except Exception` / `catch (e)` 吞掉全部异常并返回默认值，
   上层拿不到真实错误类型与堆栈，重试策略、告警分级、幂等判断全部失效。

### 判定为「合理防御」（应保留，但要登记）

1. **安全闭包 Fail-Closed**
   状态未知时**停止**操作以防资金损失 / 反作弊绕过（注意：是停止，不是放行）。
2. **非关键外围展示辅助**
   标题生成、日志截断、剪贴板兼容等，失败不影响主链路正确性。
3. **只读观测隔离**
   观测 / 诊断类查询遇到锁冲突时返回空快照；**严禁**升级为写操作。
4. **进程生命周期兜底**
   优雅退出的递进策略：RPC 通知 → SIGTERM → SIGKILL。
5. **受限环境功能适配**
   只读文件系统下降级为内存注入、无 GPU 时切 CPU 等，能力差异而非故障掩盖。

> 判定口诀：**「这次兜底之后，出问题的人还能不能知道出了什么问题？」**
> 能 → 大概率是合理防御；不能 → 就是过度防御。

## 二、检索模式（先粗筛，再逐个人工判定）

```
fallback | degrade | degraded | default_ | _default | safe_ | try_get
except Exception | except BaseException | except:          # Python
catch (error) | catch (e) | catch {}  | .catch(() =>       # JS/TS
if err != nil { return nil | _ = err | recover()           # Go
catch (\Throwable | catch (\Exception | @函数调用            # PHP
or ""  |  or {}  |  or []  |  or 0  |  ?? default          # 空值兜底
多层 .get(a, .get(b, default))  |  ?.  |  ||  链式回退
os.environ.get / os.getenv / getenv 带默认值的凭据类读取
```

## 三、交付物（四项，缺一不可）

### 交付物 1：审计报告

按以下格式输出：

**1. 全景统计**

| 指标 | 数值 |
| --- | --- |
| 回退点总数 | N |
| 过度防御数（占比） | X（X/N） |
| 合理防御数（占比） | Y（Y/N） |

**2. 评估清单表格**

| 模块 | 回退点 | 源码位置 | 判定 | 改造动作 |
| --- | --- | --- | --- | --- |
| 支付 | 汇率获取失败取上次缓存 | `pay/rate.py:88` | 过度防御 | 抛 `RateUnavailableError` |
| 观测 | 指标查询遇锁返回空 | `obs/query.go:41` | 合理防御 | 保留，登记 `obs-lock-empty` |

**3. 过度防御逐项详析**（每条一节，不要省略）

- **位置**：`file:line`（函数名）
- **触发条件**：什么异常 / 什么返回值 / 什么状态会走到这条回退
- **当前回退行为**：具体返回了什么
- **负面影响**：故障如何被掩盖、最终会在哪里以什么形态爆出来、排查会丢失哪些信息
- **改造方案**：新的异常类型名 + 报错文案原文 + 是否需要新增前置校验
- **源码片段**：改前 / 改后对照

**4. 合理防御汇总**
逐条说明为什么保留（对应上面 5 条特征里的哪一条）、以及降级事实如何被观测到
（日志字段 / 指标名 / 返回值中的 degraded 标志）。

### 交付物 2：semgrep 规则草稿

针对**本仓库真实命中的模式**，产出可直接放进 `semgrep/silent-fallback.local.yaml` 的规则：

- 规则 id 一律以 `silent-fallback-` 开头；
- 每条规则的 `message` 必须写清「为什么违规」+「两条修法」（抛错 / 走统一入口并登记）；
- 优先低误报：宁可只覆盖本仓库出现过的具体写法，也不要写宽泛模式；
- 每条规则附一段本仓库的真实命中片段作为验证样例（写进 `examples/`）。

### 交付物 3：`fallbacks.yaml` 白名单初稿

把判定为「合理防御」的条目**直接填成**可用的白名单（照抄工具包 `policy/fallbacks.example.yaml` 的字段）：

```yaml
fallbacks:
  - key: obs-lock-empty            # kebab-case，全仓库唯一
    module: obs/query
    trigger: 查询遇到表锁（pg lock_not_available），超过 200ms
    behavior: 返回空快照，标记 partial=true
    reason: 只读观测隔离；观测查询绝不升级为写操作，空快照不影响业务正确性
    owner: TODO                     # 占位，交给人填
    approved_by: TODO               # 占位，交给人填
    approved_at: TODO               # 占位，交给人填
    expires: TODO                   # 占位：必须给到期日，降级是有期限的技术债
    test: TODO                      # 占位：对应的故障注入测试标识
```

`owner / approved_by / approved_at / expires / test` 五个字段一律填 `TODO` 占位，
**不要替人编造审批信息**；提交 PR 时由人补齐，CODEOWNERS 审批即生效。

### 交付物 4：改造 PR 拆分建议

按「可独立回滚」的粒度给出 PR 拆分顺序，高危模块（资金 / 鉴权 / 数据写入）单独成 PR，
并注明每个 PR 需要补的故障注入测试。

## 四、纪律

- **不要**为了让检查通过而删掉报错、放宽 `except` 类型、或加裸 `nosemgrep`。
- **不要**替人做审批决定（owner / 到期日一律留 `TODO`）。
- 判定拿不准的条目，单独列一节「待人工裁决」，写清两种判法各自的后果，不要自行拍板。
- 报告里的每一条都必须能追溯到具体的 `file:line`，不接受「疑似存在」这类描述。

---

## 输出与落盘

四项交付物默认全部写进对话回复。仓库较大、报告很长时，可以落盘再在回复里给摘要 + 路径：

- 报告 → `docs/audit/silent-fallback-<日期>.md`
- 规则草稿 → 工具包落位下的 `semgrep/silent-fallback.local.yaml`
- 白名单初稿 → `policy/fallbacks.draft.yaml`（**不要**直接覆盖已生效的 `policy/fallbacks.yaml`，
  那个文件受 CODEOWNERS 保护，要走 PR 审批）

落盘前先问用户放哪。**本 skill 只审计和产出草稿，不直接改业务代码**——
改造由交付物 4 拆出的 PR 逐个执行，每个 PR 都要人 review。

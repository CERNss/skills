# 出站标准

`SKILL.md` 给出必须与禁止出站的清单。本文定义判定这些清单时要用的级别语义、结构约束、字段词表、量化门槛和豁免流程。

## 级别语义

四个级别按「谁会因为它做什么」划分，不按「这段代码有多重要」划分。

| 级别 | 含义 | 出站 | 典型内容 |
| --- | --- | --- | --- |
| `DEBUG` | 开发排障 | 否 | 循环内逐条处理、每条 SQL、每条消息进入、分支取值 |
| `INFO` | 业务事件与运行摘要 | 是 | 状态迁移、批次摘要、配置热更新、启动与关停 |
| `WARN` | 异常但已自愈，需要关注 | 是 | 降级、重试、超时、回退、慢请求、慢 SQL、配置回退默认值 |
| `ERROR` | 需要人介入，可以配告警 | 是 | 依赖不可用、数据不一致、无法完成的业务动作 |

三条判定规则：

- 空闲服务（无流量、无任务）必须产生 0 条 `INFO`。任何在空闲时仍然出现的 `INFO` 都是分级错误。
- 业务 4xx 不是 `ERROR`。参数校验失败、权限不足、资源不存在由调用方处理，服务端记 `Warn` 或不记。把它们记成 `Error` 会污染告警面。
- 明确忽略且没有后续动作的失败是 `DEBUG`，不是 `WARN`。日志正文里出现「best-effort」「已忽略」而级别是 `Warn` 时，级别是错的。

## 结构约束

- 一律使用 `log.Debug/Info/Warn/Error(ctx, msg, fields...)`。缺 `ctx` 的调用拿不到 `trace_id`，日志无法与 trace 关联，等于只剩一行文本。
- `msg` 必须是稳定常量，禁止拼接变量。拼接后的 `msg` 让 SigNoz 无法按 body 聚合，也无法配基于日志的告警。变量一律进字段。
- 禁止把时间戳、随机数或自增序号写进探针类日志的字段。带纳秒时间的 `zap.String("time", time.Now().String())` 会让每条 ping 日志都不同，dedup 和聚合全部失效。
- 结果与数量必须是独立字段，不能塞进 `msg` 的句子里。

## 字段词表

`trace_id`、`span_id`、`auth_user_id` 由 Izumo 自动注入，业务代码不重复写。业务字段统一 snake_case：

| 类别 | 字段名 |
| --- | --- |
| 业务 ID | `order_id`、`user_id`、`sku_id`、`card_id`、`deck_id`、`shop_id`、`message_id` |
| 运行标识 | `topic`、`job`、`run_id` |
| 结果 | `status`、`count`、`processed`、`failed`、`elapsed_ms`、`retry_count` |

同一业务对象在不同服务里必须用同一个字段名，否则跨服务查询要写多份条件。新增字段前先在本表里找同义项。

## 量化门槛

判断一条日志该不该留下时，按位置而不是按内容判断：

- 位于循环体、per-message handler、per-call 中间件或 per-row 处理里的日志，必须降为 `Debug`、加工作量门控，或聚合成批次摘要。
- tick、poll、dispatch 类日志必须门控在「本轮确实做了事」上，例如 `if processed > 0`。做不到门控就改成 metric，不要用日志计数替代 metric。
- 一个 pod 在无流量、无任务时的 OTel 日志速率必须为 0 条每分钟。这是最容易验证也最容易被违反的门槛。
- 有流量时的绝对量以 SigNoz 按 `service.name` 的日志计数为准。改造前后各取 24 小时同口径对比，把降幅写进 PR。

一次探针每 10 秒一轮、一天约 8600 条访问日志。一个仓库有 9 个探针路由时，仅探针一项每天就产生约 7.8 万条。这是判断「值不值得改」时的换算基准。

## 访问日志的唯一来源

一个进程只能有一份 access log。禁止在 Izumo 的 access log 中间件之上再注册手写的访问日志中间件，两份会把同一个请求记两次且格式不同。

同一个请求也不能在网关和后端各记一次完整访问日志。当前分工是：边缘保留带 `auth_user_id` 的采样样本，被 `tcg-gateway` 代理的后端把 `sample_rate` 再降一档，只保留错误与慢请求。禁止重复记录是硬要求，哪一侧保留样本由网关与业务方共同确认。

## 采样与门槛的分工

四个手段互不替代，按顺序使用：

1. 删除或降级。噪音的正确处理是不产生，不是过滤。
2. 访问日志采样（`sample_rate`）加排除路径（`excluded_paths`）。用于成功请求这类结构性大量、但仍需保留样本的日志。这是当前收益最大的一项。
3. severity 门槛（`OTEL_LOG_MIN_SEVERITY`）。用于噪音大、短期改不完的存量服务，是临时闸门，不是终态。现网 `DEBUG` 与 `TRACE` 占比 0.00%，把门槛设到 `info` 今天收不到量；它防的是将来有人打开 `debug`。
4. Collector 侧 filter。兜底，永远不是第一手段，见 [Collector 兜底](collector-backstop.md)。

## 豁免

以下情况允许暂不满足本标准，但必须在 PR body 写明原因、影响范围和回迁计划：

- 运行时不支持 OpenTelemetry 的历史仓（例如 PHP 5.6），只能停在本地日志。
- 事故排查窗口内临时提高级别或打开 `debug`。窗口结束必须关闭，并在同一个 PR 或后续 PR 里恢复。

长期豁免必须补 ADR。存量仓里的反例不构成新代码的依据。
